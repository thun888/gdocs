# 管理后台

管理后台地址为 `/admin`，只有 `admin` 角色可以访问。新用户默认是 `viewer`，需要通过 `oauth.bootstrap_admin` 或用户组角色获得管理员权限。

## 第一个管理员

在配置中填入登录用户的 OIDC `sub`：

```yaml
oauth:
  bootstrap_admin: ["20230001"]
```

重启服务并重新登录，该账号会变为 `admin`。`sub` 是 OIDC 返回的用户唯一标识，不是用户名。

之后可以在“用户”页确认 `sub` 和当前角色。

## 仓库来源

“仓库来源”页管理所有 Git 来源。

列表字段：

| 字段 | 说明 |
|---|---|
| 名称 | 侧栏和首页展示的名称 |
| slug | 来源标识，出现在 `/docs/<slug>` |
| 仓库 | `owner/repo` |
| 分支 | 读取的目标分支 |
| 状态 | 启用或停用 |

操作：

- **编辑**：修改来源信息。编辑时令牌留空表示不修改原令牌。
- **同步**：立即下载仓库归档并重建索引。
- **删除**：删除数据库中的来源及其文档索引，不会删除 Git 仓库。

新增来源需要填写：

- `slug`：只允许小写字母、数字和连字符。
- 名称、仓库地址、访问令牌、owner、repo、分支、子目录、排序。
- 令牌需要具备目标仓库的读写权限；只读场景至少需要读取仓库内容和归档的权限。
- 分支为空时默认 `main`。
- 子目录为空表示仓库根目录。

注意：配置文件中 `sources` 只用于首次初始化。已存在的 slug 不会被配置覆盖。删除由配置初始化的来源后，重启服务会再次创建；要永久删除，需要同时从配置中移除。

## 用户组

用户组来自 OIDC 登录声明中的 `groups`，在用户登录或令牌刷新时同步。

| 字段 | 说明 |
|---|---|
| 组标识 | 上游返回的组 code |
| 类型 | code 中冒号前的部分，例如 `unit` |
| 成员 | 当前站点中属于该组的人数 |
| 角色 | 该组在站点的角色：`viewer`、`editor`、`admin` |
| 忽略 | 勾选后该组不参与角色计算 |

规则：

- 新同步的组默认是 `viewer`。
- 一个用户属于多个组时，取未忽略组中的最高角色。
- 组角色修改后，用户下次登录或令牌刷新时生效。
- 上游已经删除的组不会自动从数据库中移除。

常见做法：

- 把某个部门组设为 `editor`，组内成员都能编辑文档。
- 只把运维组设为 `admin`。
- 用“忽略”排除不参与权限的组。

## 用户

“用户”页是只读列表，展示：

- 姓名
- 学号/工号（OIDC `sub`）
- 当前角色
- 所属用户组
- 最近登录时间

站点不支持手动修改单个用户的角色。角色由 `bootstrap_admin` 和用户组共同决定。

## 站点设置

“站点设置”页可以修改：

- 站点名称：显示在顶栏和浏览器标题。
- 站点介绍：保存在数据库，供站点信息接口使用。

这些设置保存在 PostgreSQL 的 `settings` 表中，不写回 `config.yaml`。

## 索引维护

文档索引是 PostgreSQL 中的目录元数据缓存，正文仍以 Git 为准。

索引更新时机：

- 服务启动时预热。
- 访问目录树时超过 `index.ttl_minutes` 自动刷新。
- 站点内新建、保存、移动、删除、导入、排序后，如果 `index.sync_on_write: true` 会立即刷新。
- 管理后台点击“同步”会强制刷新。

需要手动同步的情况：

- 有人直接在 Forgejo 提交或修改了文档。
- 侧栏内容和仓库不一致，但还没到自动刷新时间。
- 修改了来源的仓库、分支或子目录。

同步失败时查看服务日志。常见原因是令牌无效、仓库为空、分支不存在或归档超过大小上限。
